# Incident report INC-4933: orders-db volume filled by WAL

Severity: SEV1
Status: monitoring
Duration: 1 hour 12 minutes
Services: orders-db, checkout-api, storefront

## Summary

orders-db stopped accepting writes when its data volume reached 100%. checkout-api
returned 503 for checkout because inserts failed; reads continued, so pods stayed
Ready. storefront logged `upstream_status=503` for `POST /checkout`.

## Root cause

A replication slot for a decommissioned replica was never dropped. PostgreSQL
retained all WAL for the slot until the volume filled.

## Evidence

- orders-db: `PANIC:  could not write to file "pg_wal/xlogtemp.88": No space
  left on device` and `ERROR:  could not extend file`.
- checkout-api: `psycopg2.errors.DiskFull` on insert; readiness still passing.
- storefront: `upstream_status=503`, not connection refused.

## Resolution

Dropped the inactive slot with `pg_drop_replication_slot`, checkpointed, and
expanded the volume from 20Gi to 50Gi.

## Action items

- Alert on inactive replication slots. Status: done.
- Disk usage alert at 70%. Status: done.
