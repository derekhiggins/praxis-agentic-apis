# Incident report INC-4821: checkout-api could not resolve legacy database hostname

Severity: SEV2
Status: resolved
Duration: 25 minutes (staging), no production impact
Services: checkout-api

## Summary

After the database move to the `orders-db` StatefulSet, a checkout-api release
still set `DATABASE_HOST=checkout-db`. The legacy `checkout-db` Service had been
removed, so new pods crashed at startup and entered CrashLoopBackOff.

## Evidence

- checkout-api previous container log: `psycopg2.OperationalError: could not
  translate host name "checkout-db" to address: Name or service not known`.
- Pods in CrashLoopBackOff with rising restart counts; no readiness probe events.

## Resolution

Set `DATABASE_HOST=orders-db` in the Helm values and rolled out. Alias Services
were rejected because they hide stale configuration.

## How to tell it apart

DNS failures crash the container at startup. Authentication failures (INC-4867)
keep the container running but NotReady.
